## 1. `stateurls/` — 58 markdown files

- **Format**: 58 `.md` files, 1.1 MB total (`inventory.json`). Two are byte-identical duplicates (`01a016f5-5bcc-...md` and `...(1).md`, confirmed via SHA-256).
- **Content**: not curated per-state statute/regulation link lists. They are raw Firecrawl page dumps of `https://www.justice.gov/jmd/ls/state/<state>` (the DOJ "State and Federal Court Resources" index and its 56 state sub-pages, plus the federal page and the state index page). Confirmed by direct inspection: page bodies are DOJ nav/share-widget HTML-to-markdown plus an embedded links table per state (attorney general, state courts, state bar, state legislature, state code/statutes site, U.S. Attorney's office, etc.).
- **Measured**: 3,362 non-navigation content links across the 58 files, 1,525 distinct hosts. Top hosts: justice.gov (214, self-links), publicrecords.netronline.com (52), library.municode.com (47), findlaw.com (46), codelibrary.amlegal.com (41), generalcode.com (30), state .gov court/legislature sites (~10–25 each).
- **Dates**: filenames carry capture timestamps of **2026-08-18** (e.g. `...htm.2026-08-18T22_24_04.508Z.md`); UUID-named files have no visible capture date in the body.
- **Already in SCRAPE**: `sources/doj_state_resource_map_20260919/pages.jsonl` captures the *same* 58 `justice.gov/jmd/ls/*` URLs (58 exact URL matches confirmed) but from a **2026-09-13** re-capture recorded via `catalog/documents.sqlite3` versions, with full provenance (sha256, capture_version_id, link_count, etc.) — a materially better artifact than these plain markdown dumps. STATE.md's "doj_state_resource_map (56 pages, 3,201 links)" is this newer capture; the 3,362 vs 3,201 link-count difference is consistent with 58 files here vs 56 pages counted there (2 extra files = federal index + state index page, not counted as "state" pages).
- **Gap mapping**: would touch **G14** (source directories) and **G9/G5** context, but is fully superseded.
- **Join key**: none needed — no build recommended.
- **Quality risk**: stale (5 weeks older than the corpus's own capture), one exact duplicate file, encoding artifacts (mangled non-ASCII quotes, e.g. "�external link�") that the newer capture likely also has to handle.
- **Effort**: — (do not build; historical curiosity only).

## 3. `phase1_directory_contract_v3_2026-08-22/`

- **What it is**: a formal identity/canonicalization **contract** (`contract/directory_contract_v3.json`, `contract_version: "3.0.0-phase1"`) plus a tested Python engine (`src/directory_phase1.py`, `phase1_runner.py`, `source_adapters.py`, `verify_outputs.py`) that ran a **dry run** (no writes, no network, no promotion) over **20 configured sources** and **4,991,477 input records**, producing `dry_run/gate_1_final_v2/reconciliation_report.json`.
- **Status flag, verified**: `"status": "phase1_dry_run_not_promoted"` in the contract; `CURRENT.md` states explicitly "Phase 1 remains dry-run evidence only. It authorizes no network mapping, downloads, source restructuring, Supabase writes, or promotion into a canonical registry." Two independent full runs were byte-identical (semantic digest `1f828c5...096ec` matches across `run_1`/`run_2`/final).
- **Measured totals** (`reconciliation_report.json.aggregate.totals`): 4,991,477 input records → 2,742,377 raw URLs → 2,125,519 distinct canonical URLs (4,342 canonical-equivalence collapses, 612,384 exact-duplicate surplus, 0 adapter errors, 0 conservation delta — i.e. the reconciliation itself is internally consistent). 2,157,406 records had no URL at all (`missing_url_records`); 381,422 were non-URL record types; 120 were invalid URLs.
- **The 20 per-source rows** are keyed only by opaque `src:<sha256>` ids in this report — the human-readable source names live in `contract/source_crosswalks_v1.json` (not opened in depth here — **unmeasured** which named source maps to which hash, beyond recognizing raw-URL-count fingerprints: two rows at exactly 362,331/362,333 raw URLs strongly suggest the same `court_expansion_url_corpus_v2` seen in section 2c/gz sample below; one row at 1,018,515 raw URLs is by far the largest single source and unidentified here).
- **Independent gz sample check**: `court_expansion_url_corpus_v2.jsonl.gz` (in the superseded archive, see §4) streamed to **361,741 rows** — schema is per-URL: `url`, `host`, `url_node_id`, `associated_court_ids[]`, `authority_lanes[]`, `authority_statuses[]`, `discovery_methods[]`, `jurisdiction_codes[]`, `quality_flags[]` (e.g. `non_https_discovery_url`), `registry_writes` (0 for sampled rows), `direct_file_candidate`. This is consistent with (not necessarily identical to) the raw-URL counts referenced by the phase1 dry run and by `source_gap_reconciliation`'s baseline.
- **Is this a dataset to ingest?** No — it's tooling + a proof that the tooling conserves records/URLs correctly over a large multi-source corpus. Its practical value to SCRAPE is as a **design reference for G13** (the canonical-id/relationship-graph gap): the contract's `identity_recipe` (sha256 over `source_file_id|record_locator|raw_record_sha256` etc., U+001F separator, explicit `canonical_resource`/`url_alias`/`source_record` record classes) and its `url_normalization_profile` (explicit allow-list of safe transforms, an explicit deny-list of transforms requiring evidence like `http_to_https`/`www_host_collapse`, and a `secret_query_parameter_names` redaction list) are a more rigorous version of the ad hoc URL-matching used elsewhere in this cluster (e.g. §2c's "exact normalized match").
- **Already used in SCRAPE**: no grep hits for `phase1_directory_contract` in `sources/`/`delivery/`.
- **Effort**: N/A to "ingest" (no rows); **L** if a builder wants to adopt this identity contract as SCRAPE's own canonical-id scheme, since it would mean re-deriving ids for existing layers to match its recipe.
